    Use from a test

    Point your client at sftpit. In your test, turn a fault on with an HTTP request, run your code, then check how it handled the failure. This works from any language.

    1 Turn a fault on

    
          
    The faults on the dashboard, by name. Add "first": 1 to apply it only once. GET /api/presets lists every option.
    
        
    
        
    
          
    2 Run your code, then check the fault happened
    
          
    
          
    happened counts how many times the fault took effect. If it is 0, the test did not exercise the failure.
    
        
    
        
    
          
    3 Clean up between tests
    
          
    
          
    Turns every fault off and restores the starting files.
    
        
    
      
    
      
    
        
    Replacing an SFTP server you already run in tests
    
        
    Run sftpit instead. Port 2122 serves SFTP; port 8122 serves this dashboard and the API. Requests that change anything must include the Sftpit-Control header. Browsers can’t send it from other websites, so a web page can’t change sftpit.
